## 《Structured information extraction from scientific text with large language models》

**来源：** *Nature Communications (2024)*  
**作者：** Krenn 等  

---

## 🧭 一、研究动机与问题提出

> **问题背景：**  
> 科学论文中包含大量关于材料、化学和实验结果的重要信息，但这些信息往往以**自然语言**形式存在，难以直接用于数据库或知识图谱。

> **研究目标：**  
> 提出一种简单、通用的 **大型语言模型（LLM）结构化信息抽取方法**，  
> 实现从科学文本中联合识别“命名实体（NER）”与“关系（RE）”，并输出结构化结果（如 JSON）。

**以往问题：**

- 依赖规则或特定领域的 NLP 系统，可迁移性差。  
- 人工标注成本高，数据集规模受限。  

---

## ⚙️ 二、方法概述：LLM-NERRE 框架

### 核心思路

- 使用 **序列到序列（seq2seq）微调策略**，让模型直接生成结构化信息。
- 模型输入：科学句子或摘要  
  模型输出：按照预定义 schema 的结构化结果（JSON 或自然语言格式）。

### 模型

- **GPT-3（175B）**：API 微调  
- **LLaMA-2（70B）**：LoRA 微调（r=8, α=32, dropout=0.05，8-bit量化）  
- 训练样本仅需约 100–500 条。  

---

## 🧩 三、三个任务与数据来源

| 任务名称                        | 领域      | 数据来源                 | 文本层级 | Schema 类型                             | 数据规模           |
| --------------------------- | ------- | -------------------- | ---- | ------------------------------------- | -------------- |
| **Doping**（掺杂）              | 固态材料掺杂  | 162 篇论文摘要中筛选的掺杂句子    | 句子级  | Doping-JSON / English / Extra-English | 413 训练 / 77 测试 |
| **MOF**（金属有机框架）             | MOF 材料  | 507 篇 MOF 相关摘要       | 摘要级  | MOF-JSON                              | 507            |
| **General Materials**（通用材料） | 多领域材料科学 | 634 篇摘要（半导体、陶瓷、高分子等） | 摘要级  | General-JSON                          | ~650 条标注样本     |

**示例 Schema（General-JSON）：**

```json
{
  "name": "barium titanate",
  "formula": "BaTiO3",
  "acronym": "BTO",
  "description": "ferroelectric perovskite oxide",
  "structure_or_phase": ["perovskite"],
  "applications": ["dielectric capacitors", "actuators"]
}
```

## 📊 四、评测指标体系

### （1）自动化指标：Exact Word-Match F1

- 基于**逐词精确匹配**（严格字符串比较）。

- 要求模型预测的实体或关系与人工标注**完全一致**。

- 对化学式、大小写、标点敏感。

- 若输出 JSON 无法解析 → 记为错误。

**计算公式：**

Precision=TP+FPTP​,Recall=TP+FNTP​,F1=P+R2PR​

**评估维度：**

- **NER F1**（命名实体识别）

- **RE F1**（关系抽取）

- **NERRE F1**（联合评估）

⚠️ **局限：** 对语义等价表达不宽容（例如 “BaTiO3” ≠ “barium titanate”）

---

### （2）人工指标：Manual / Expert Evaluation

- 抽取测试集约 **10% 样本**，由两名材料领域专家人工判定。

- 判断标准：
  
  - 语义一致且字段正确 → 记为正确；
  
  - 信息缺失或关系错误 → 记为错误；
  
  - 部分正确 → 仲裁后决定。

**意义：**

- 反映模型在科研实际应用中的**上界性能（upper bound）**。

- 弥补 strict-match F1 的低估。

**示例：**

| Task         | Field        | Exact F1 | Manual F1 |
| ------------ | ------------ | -------- | --------- |
| General-JSON | formula      | 0.429    | **0.943** |
| General-JSON | applications | 0.512    | **0.832** |

---

## 🧠 五、人机协同数据构建（Human-in-the-loop）

> **核心思想：**  
> 让模型参与标注过程：由模型进行初步标注，人工再进行修正与扩充，从而显著降低标注成本。

### 流程：

1. **人工初始标注**：人工构建 50–100 条高质量样本。

2. **初步微调模型**：用少量样本微调 LLM，得到中间模型。

3. **模型预标注**：中间模型对新文本生成结构化输出（JSON）。

4. **人工修正**：人工审阅、修改错误字段（如 dopant/host 对调）。

5. **数据扩充 + 再训练**：将修正数据加入训练集，形成迭代循环。

**效率提升结果：**

| 训练样本数量（中间模型） | 人工时间占比  | 效率提升     |
| ------------ | ------- | -------- |
| 1（无模型）       | 100%    | —        |
| 50           | 68%     | ↑32%     |
| 100          | 57%     | ↑43%     |
| 300          | **43%** | **↑57%** |

> 📈 **结论：**  
> 即使只使用约 300 条样本训练的中间模型，也能使人工标注时间减少约 57%。  
> 模型的“半正确输出”让人工更高效地理解 schema、快速修正。

| 任务      | 模型      | Schema        | Exact F1  | Manual F1     | 说明          |
| ------- | ------- | ------------- | --------- | ------------- | ----------- |
| Doping  | LLaMA-2 | JSON          | **0.821** | ≈0.87         | 结构最清晰       |

**总结发现：**

- GPT-3 更擅长自然语言输出；

- LLaMA-2 更擅长 JSON 格式；

- Manual 评分显示模型语义理解远超严格匹配结果。

## ⚠️ 七、讨论与局限

| 问题                    | 描述             | 解决思路                   |
| --------------------- | -------------- | ---------------------- |
| **Exact 匹配过严**        | 忽略语义等价表达       | 引入语义相似度指标（如 BERTScore） |
| **JSON 可解析性**         | 少数样本生成无效 JSON  | 增加格式约束与验证步骤            |
| **幻觉（hallucination）** | 模型可能生成文中不存在的事实 | 限制生成实体必须出现在源文中         |
| **人工成本仍存在**           | 虽显著降低但未完全消除    | 继续优化人机循环策略             |
| **领域泛化**              | 目前聚焦材料科学       | 可扩展至生物、药物等领域           |

## 💡 九、启示与总结

1. **方法简洁**：基于 LLM 的端到端结构化生成，无需复杂架构。

2. **数据效率高**：百级样本即可获得可用性能。

3. **人机协同高效**：预标注+人工修正显著降低成本。

4. **评测更全面**：结合 strict-match 与 semantic-match 评估体系。

5. **可迁移性强**：通用 schema 可推广至其他科学文本抽取场景。

## ✅ 十、总结

- LLM 可实现科学文本信息结构化抽取的通用框架。

- Exact-match 与 Manual 评估结合提供上下界性能。

- 人机协同标注策略是关键创新点。

- 不同 schema（JSON vs English）影响模型表现。

- 未来可扩展到跨领域科学知识抽取。

## 《Data extraction from polymer literature using large language models》

**来源：** *Communications Materials (Nature Portfolio, 2024)*  
**作者：** Krenn et al.

---

## 🧭 一、研究动机与总体目标

> **研究背景：**  
> 材料科学文献中包含大量关于聚合物及其物性的宝贵信息，但这些信息以非结构化自然语言存在，难以直接转化为可计算数据库。  

> **核心目标：**  
> 开发一个可扩展的**大型语言模型（LLM）驱动的自动信息抽取管线**，从超过 **240 万篇材料科学论文**中提取**聚合物—属性—数值—单位**四元组，构建结构化数据集。  

**主要挑战：**

- 文献表达形式多样（公式、缩写、非标准单位）；
- 缺乏大规模人工标注数据；
- 需要平衡准确度、泛化性与计算成本。

---

## 🧩 二、任务体系概览

论文提出了一个由 **三大任务（tasks）** 构成的多层抽取框架：

| 阶段         | 任务名称                         | 核心目标                                      | 输入来源                     | 输出结果        |
| ---------- | ---------------------------- | ----------------------------------------- | ------------------------ | ----------- |
| **Task 1** | Heuristic Filtering（启发式筛选）   | 从数百万篇文献中筛选出可能包含聚合物属性信息的段落                 | 2.4M 材料科学论文（HTML/XML 全文） | 2.6M 属性相关段落 |
| **Task 2** | NER Filtering（命名实体识别过滤）      | 找出同时包含材料名、属性、数值、单位的段落                     | Task 1 输出（2.6M 段落）       | 716k 高置信段落  |
| **Task 3** | Information Extraction（信息抽取） | 从段落中抽取结构化四元组：Material–Property–Value–Unit | 716k 段落                  | 1M+ 条结构化记录  |

---

## ⚙️ 三、任务详解

### 1️⃣ Task 1：启发式筛选（Heuristic Filtering）

**目标：** 从全语料中筛出潜在的聚合物属性描述。  
**方法：**

- 构建 24 种属性关键词表（如 *glass transition temperature*, *tensile strength*, *modulus*, *conductivity* 等）。  
- 匹配关键词及其变体，保留相关段落。

**结果：**

- 初始段落：23.3M  
- 筛选后保留：2.6M 段落  
- 来源论文：约 681,000 篇含“poly”前缀的聚合物论文。  

---

### 2️⃣ Task 2：NER Filtering（命名实体识别过滤）

**目标：** 进一步筛选具有完整信息的段落。  
**方法：**

- 使用 **MaterialsBERT** 模型识别四类实体：
  - Material（材料）
  - Property（属性）
  - Value（数值）
  - Unit（单位）
- 若段落缺任一实体类型则剔除。

**结果：**

- 从 2.6M → 716k 段落  
- 大幅降低 LLM 推理成本。  

---

### 3️⃣ Task 3：Information Extraction（信息抽取）

**目标：** 从高置信段落中抽取结构化记录。

| 路线               | 模型                       | 特点           | 输出           |
| ---------------- | ------------------------ | ------------ | ------------ |
| **NER Pipeline** | MaterialsBERT + 启发式规则    | 轻量级、可解释性强    | 表格化数据        |
| **LLM Pipeline** | GPT-3.5 / LLaMA-2 + 指令提示 | 高灵活性，可处理复杂句式 | JSON 格式结构化输出 |

**数据示例：**

```json
{
  "material": "PMMA",
  "property": "glass transition temperature",
  "value": "105",
  "unit": "°C"
}
```

## 🧩 五、评测集与评测逻辑

### （1）两类文献集合

| 集合             | 数量        | 是否人工标注 | 用途                |
| -------------- | --------- | ------ | ----------------- |
| **630 篇人工标注集** | 951 条样本   | ✅ 是    | 精确评测与 few-shot 示例 |
| **1000 篇评估集**  | 含上面 630 篇 | ✅ 部分   | 泛化与规模化评估          |

> 📘 设计逻辑：
> 
> - 630 篇 → 有真值，用于计算 F1；
> 
> - 1000 篇 → 包含未标注样本，用于测试泛化与覆盖率。

---

### （2）评测方式

**评测目标：**  
验证模型是否能正确抽取四元组 `Material–Property–Value–Unit`。

**判定规则：**

- 只有当预测结果与人工标注出现在**同一段落**时，且四个字段**完全一致**，才记为正确（True Positive）。

- 其他情况计为错误（FP / FN）。

**指标计算：**

Precision=TP+FPTP​,Recall=TP+FNTP​,F1=P+R2PR​

---

## 🧮 六、评测层级设计：段落匹配 × 篇级汇总

| 层级                       | 说明                                                   |
| ------------------------ | ---------------------------------------------------- |
| **段落级（Paragraph-level）** | 模型输入与匹配单位。每个段落独立送入 LLM，输出 JSON；若结果与人工标注在同一段落出现则记为正确。 |
| **篇级（Article-level）**    | 聚合单位。将每篇文章中 TP、FP、FN 累积后计算宏平均 F1，用于整体性能报告。           |

> ✅ 匹配单位 = 段落  
> ✅ 汇总单位 = 篇
> 
> **段落粒度** 保证语义准确（避免跨段幻觉），  
> **篇级汇总** 反映总体性能（方便分析泛化与覆盖）。

---

## 📊 七、评测结果（概要）

| 模型                            | 属性      | Precision        | Recall | F1       | 特点          |
| ----------------------------- | ------- | ---------------- | ------ | -------- | ----------- |
| **GPT-3.5 (similar-shot)**    | Tg      | 0.90             | 0.83   | **0.86** | 表达最灵活、幻觉率最低 |
| **LLaMA-2 (LoRA fine-tuned)** | Tg      | 0.78             | 0.72   | 0.75     | 需更大样本支持     |
| **MaterialsBERT (NER)**       | Tg      | 0.71             | 0.69   | 0.70     | 高速但上下文捕获能力弱 |
| —                             | Bandgap | 相对较低 (~0.65–0.8) | —      | GPT 仍领先  |             |

> GPT-3.5 few-shot（尤其是 similar-shot 策略）在两种属性上均取得最佳 F1。

---

## 📘 八、总结

- 本文通过三阶段（启发式过滤 → NER → LLM 抽取），  实现从 240 万篇材料文献中自动抽取结构化聚合物数据。

- 模型评测采用“段落级判定 + 篇级汇总”的双层体系，  结合 630 篇人工标注与 1000 篇整体语料，实现了准确性与泛化能力的平衡。

- GPT-3.5 在 few-shot 提示下表现最佳，  展示了 LLM 在科学信息结构化中的巨大潜力。

## 《Large language models reveal big disparities in current wildfire research》

**来源：** *Communications Earth & Environment (Nature Portfolio, 2024)*  
**作者：** Zhengyang Lin, Anping Chen, Xuhui Wang, Zhihua Liu, Shilong Piao

## 🧭 一、研究目的与总体设计

> **研究目标：**  
> 使用大型语言模型（LLM，GPT-3.5-turbo）对 1980–2022 年间的**全球野火研究文献（60,488 篇）**进行自动化分类与地理信息提取，以发现学科与区域间的研究不均衡现象。  

> **研究逻辑：**  
> 
> 1. 从 Web of Science 检索全部“野火（wildfire）”相关论文；  
> 2. 利用 LLM 自动识别研究主题与地理位置；  
> 3. 与卫星观测的火灾面积、排放、社会经济数据进行对比分析。

## ⚙️ 三、分析与抽取方法（Analysis and Extraction Methods）

### （1）LLM 信息抽取框架

使用 **OpenAI GPT-3.5-turbo** 模型（无微调）通过 API 调用执行以下任务：

| 模块                                | 任务说明                                                                                | 输出信息           |
| --------------------------------- | ----------------------------------------------------------------------------------- | -------------- |
| **文本判定**                          | 判断文献是否与野火研究相关（1/0）                                                                  | relevance flag |
| **主题分类**                          | 从预设主题池中识别主要研究方向（vegetation, atmospheric, anthropogenic, modeling, remote sensing 等） | 主/次主题标签        |
| **研究元信息提取**                       | 识别文献类型、研究阶段（pre-fire, burning, post-fire）、研究时间段                                     | 分类元数据          |
| **地理位置解析（Geoparsing）**            | 从标题与摘要中抽取地理实体，转换为数值坐标（最大外包围 MOB、中心点 CP），并生成 ISO-3166 国家代码                           | 经纬度 + 区域代码     |
| **火源分类（Ignition Classification）** | 自动判定火源类别（human-caused / natural / mixed）                                            | ignition type  |

> ⚙️ **技术实现要点：**
> 
> - 采用 prompt-based pipeline（非特征工程）；
> - 对每篇文献生成独立的 JSON 结构；
> - 坐标统一到 1° 栅格分辨率；
> - 输出可直接映射到地理空间数据。

### （2）Prompt 设计示例（关键提取结构）

#### 🔹 文献主题与元信息提取

“You are a perfect classifier.List all the following contents and start with a
 newline.I would like you to (not specific or not applicable marked as N/Az): ...."

#### 🔹 地理位置解析（Geoparser）

“You are an accurate geoparser with outputs in 1° spatial resolution (per
 grid). Parse the following text into separate regions. Start with a new
 paragraph for every single region. Define the maximum outer boundary as

 CP. All the MOB and CP are recorded in the pairs of (latitude, longitude)
 and integers.
 (1) if it is a qualified geographical location:
 (a) no smaller than the area of 1 grid, list the parsed name and MOB;

nations should be returned.”
